# 跨数据集泛化：把 CWRU 轴承公开数据集接进 Agent

> 目的：回答工业界的第一问——"你只对自己造的数据有效吧？"。做法是把一个**外部公开、带故障
> 标签**的数据集接成 `EvidenceSource`，**Agent / 工具链一行不改**，看结果。

## 0. 数据与方法

- 数据：**CWRU 轴承故障数据集**（Case Western Reserve University；第三方镜像仓库
  `AiChiXiaoXiongBingGan/CWRU-dataset`，原始出处 case.edu）。本机落在 `data/cwru/`（**gitignore**）。
- 9 个文件（1 正常 + 3 外圈 + 3 内圈 + 2 滚珠），每条 DE 振动信号切 4 个 24k 点窗口
  → **36 个窗口**（normal 4 / ball 12 / inner 8 / outer 12）。
- **零新依赖**：MAT v5 未压缩，`evidence/cwru.py` **手写最小解析器**——刻意**不把 scipy
  加进项目依赖**（本机后来装上了 scipy 1.18.1，但代码不依赖它）。
- 信号 → 诊断特征：RMS / 峰值 / **峭度** / **波峰因子**（经典轴承诊断量）。Agent 看到的是标量，
  不是 12 万点原始波形（省 token，且与遥测证据形态一致）。
- 组件固定 `bearing.main`；`CWRUEvidenceSource` **自带授权校验**（它不属于机器人电机拓扑）。

## 1. 结果（2026-10-12，model=deepseek-v4.1）

| 栏 | accuracy | 故障召回 | normal 误报 | ball / inner / outer 命中 |
|---|---|---|---|---|
| 确定性阈值基线（kurtosis>4 或 crest>5） | **0.75** | 0.719 | 0.0 | 7/12 · 8/8 · 8/12 |
| **真 LLM Agent** | **0.75** | 0.719 | 0.0 | 7/12 · 8/8 · 8/12 |

## 2. 三条结论（都要如实读）

1. **"换数据源、Agent / 工具链不改"成立**：整个接入只新增了一个证据源模块——
   `AgentLoop` / `InvestigationTools` / 工具契约**没动一行**。这是本仓"换数据源只替换合成层"
   设计的兑现。
2. **判据不迁移**：故障召回只有 **0.719**——**约 28% 的轴承故障被漏掉**。原因清楚：阈值
   （kurtosis > 4 / crest > 5）是从**合成档借来的、没在 CWRU 上标定**。跨数据集不是"接上就行"，
   **必须重新标定**（与 `docs/mujoco_dataset.md` 对评估器判据的诚实口径一致）。
3. **LLM 这一栏没有增量**：它与阈值基线**逐条一致**（0.75 / 0.719 / 0.0）。因为工具只给了 4 个
   标量 + 一份厂商阈值，Agent 能做的就是"照阈值判"——**证据不足时，Agent 只能等于阈值**。
   这反过来指出提分方向：给更有区分度的证据（包络谱 / 缺陷频率 BPFO/BPFI/BSF），或让 Agent
   看到更长、多窗的上下文。

## 3. 边界

- 标签**粗粒度**（normal vs 任一故障），不区分缺陷类型；`by_fault` 只报"是否识别出异常"。
- 同一条信号切出的窗口**高度相关**：n=36 是**窗口数**，不是独立试验数 → CI 要打折。
- 阈值**未标定**（见 §2.2）；窗口长度 24k（2 s @ 12 kHz）是起始选择，未做敏感性分析。
- 复现：下载 `data/cwru`（见脚本内 FILES 清单）后
  `python scripts/cwru_eval.py --windows-per-file 4 --workers 4`。

## 4. 第二轮：富证据（包络谱 + 缺陷频率）

时域特征（RMS / 峭度 / 波峰因子）对**早期微弱缺陷不敏感**；轴承诊断的经典做法是看**包络谱**
在缺陷频率处的能量：

- 缺陷频率由轴承几何 + 转频决定（6205-2RS JEM SKF：BPFO≈3.5848·fr、BPFI≈5.4152·fr、
  BSF≈4.7135·fr、FTF≈0.3983·fr）；
- 包络用 **numpy FFT 自实现 Hilbert**（**零新依赖**，不引 scipy）；
- 产出 `env_bpfo / env_bpfi / env_bsf` = 缺陷频率及其 2~3 次谐波 ±3% 带内能量 /
  10 Hz–2 kHz 总能量（**比值**，不受增益 / 量纲影响）；
- ⚠️ 转速用**标称值**（`LOAD_RPM`：0/1/2/3 HP → 1797/1772/1750/1730 rpm）——本镜像仓库的
  `XnnnRPM` 变量是**空的**，这是**假设**不是实测。

厂商知识同步补上包络阈值与"哪个频率抬升对应哪类缺陷"。

### 4.1 富证据下，LLM 终于超过阈值基线（39 窗口，op_0 + op_1）

| 栏 | accuracy | 故障召回 | ball / inner / outer |
|---|---|---|---|
| 阈值基线（旧阈值） | 0.744 | 0.697 | 5/12 · 9/9 · 9/12 |
| **真 LLM（含包络证据）** | **0.897** | **0.879** | 9/12 · 9/9 · 11/12 |

- **第一轮（只有时域特征）LLM 与基线逐条一致**；加上包络证据后 **+0.18 accuracy / +0.18 召回**。
  结论：**Agent 的价值取决于证据质量**——证据只有 4 个标量时它只能等于阈值；给它缺陷频率，
  它才真的多认出东西来。

## 5. 第三轮：判据重标定（按载荷 held-out）

**为什么按载荷切**：同一条信号切出的窗口高度相关，随机切训练 / 测试 = **数据泄漏**（CWRU 文献
里那些 99%+ 多半如此）。按载荷切才是"换工况还灵不灵"。

做法：在 **op_0（0 HP）** 上按平衡准确率扫**单特征阈值**（保持确定性、可解释），在
**op_1（1 HP）** 上评估。

| | 测试 accuracy | 故障召回 | normal 误报 |
|---|---|---|---|
| 旧阈值（kurtosis>4 或 crest>5） | 0.75 | 0.667 | 0.0 |
| **重标定**（`rms > 0.0737`） | **1.00** | **1.00** | 0.0 |

- 标定集上 `rms / peak / kurtosis / env_bpfo` 都能到 bal_acc 1.0 → 这一批 CWRU
  （0.007 / 0.014 / 0.021″ 三档）**可分性本就很强**：问题从来不是"分不开"，而是**旧阈值定错了**。
- 测试集 op_1 只有**最弱**的 0.007″ 缺陷，仍全部召回 → 标定**迁移了**，不是背了 op_0。

### 5.1 三栏放一起看

| 判据 | accuracy | 故障召回 | 需要人工标定？ |
|---|---|---|---|
| 旧阈值（借合成档） | 0.744 | 0.697 | — |
| **真 LLM + 包络证据** | **0.897** | **0.879** | **不需要**（换数据集直接跑） |
| 重标定单阈值（跨载荷） | 1.00 | 1.00 | **需要**（有标签的标定集上扫） |

**结论**：在这个数据集上，**精心标定的单阈值仍然最强**；Agent 的价值不是"更准"，而是
**不依赖逐数据集人工标定**就能从 0.70 拉到 0.88。换句话说——**能标定就标定，标不了才靠 Agent**；
这正好解释了本仓"热路径用确定性阈值、Agent 只做调查"的分工。

### 5.2 边界（第三轮）
- 只有 **2 个载荷**、op_1 仅 16 窗口（normal 4）→ CI 很宽；阈值能否跨到 op_2/op_3 **未验**。
- "单特征阈值 bal_acc=1.0" 在小标定集上**容易过拟合**；这里选的是 rms，物理上也说得通
  （缺陷提升振动能量），但**不代表换个数据集还会是它**。
- 复现：`python scripts/cwru_recalibrate.py --calib-load 0 --test-load 1`。

## 6. 第四轮：留一载荷交叉验证（4 载荷 / 84 窗口）

单折容易骗人。**留一载荷（LOLO）**：每个载荷轮流当测试集、其余当标定集。

| 测试载荷 | 重标定规则 | 旧阈值 acc / 召回 | 重标定 acc / 召回 | 重标定 normal 误报 |
|---|---|---|---|---|
| op_0（0 HP） | rms>0.0668 | 0.750 / 0.719 | 0.889 / 1.000 | **1.00** |
| op_1（1 HP） | rms>0.0737 | 0.750 / 0.667 | 1.000 / 1.000 | 0.00 |
| op_2（2 HP） | rms>0.0737 | 0.750 / 0.667 | 1.000 / 1.000 | 0.00 |
| op_3（3 HP） | rms>0.0737 | 0.750 / 0.667 | 1.000 / 1.000 | 0.00 |
| **聚合** | — | 0.750 / 0.691 | **0.952 / 1.000** | **0.25** |

1. **召回可迁移**：旧阈值在 4 个载荷上都漏 ~30%；重标定后**每一折召回都到 1.00**，且四折
   一致选中 **rms**、阈值几乎相同（0.0668~0.0737）——标定**稳定，不是瞎碰**。
2. **误报不是免费的**：op_0 那一折的 normal **全被误报**（FP=1.00）——标定集（op_1+2+3）选出的
   `rms>0.0668` 恰好压在 op_0 的正常水平之下。聚合 FP = **0.25**。**"换个工况照样零误报"是假的。**

### 6.1 真 LLM（含包络证据）在 4 载荷上的对照（84 窗口）

| 判据 | accuracy | 故障召回 | normal 误报 | 需要人工标定？ |
|---|---|---|---|---|
| 旧阈值（借合成档） | 0.750 | 0.691 | 0.00 | — |
| **真 LLM + 包络证据** | **0.821** | **0.779** | **0.00** | 不需要 |
| 重标定单阈值（LOLO 聚合） | **0.952** | **1.000** | **0.25** | 需要 |

- LLM **稳定高于未标定基线**（+0.07 acc / +0.09 召回），且**不牺牲误报**（FP 仍 0）。
- ⚠️ **诚实修正**：两载荷那轮 LLM 是 0.897 vs 0.744（+0.18）；扩到 4 载荷后 lift 收敛到
  **+0.07**——**那 +0.18 有一部分是采样运气**。引用时用 4 载荷这组。
- 三者的取舍很真实：**标定换召回、代价是误报；Agent 不换误报、召回中等；不标定两样都差。**
  选哪个取决于"漏报 vs 误报"哪个更贵。

### 6.2 边界
- 每折 normal 只有 4 个窗口（全库 16），FP 的 CI 极宽；要定误报率得补更多**正常**数据。
- op_0 的 normal 文件样本数（243,938）与其他不同，窗口相关性更高。
- 复现：`python scripts/cwru_recalibrate.py --lolo`（标定）、
  `python scripts/cwru_eval.py --windows-per-file 4`（LLM）。
