# MuJoCo 忠实仿真数据集 —— 生成与评估

> 用 MuJoCo 加载 Go2 真实四足模型，自写 trot 步态控制器产出**自由基座真走路**的
> 物理自洽遥测，叠加真实噪声模型与 5 类故障，批量生成**万级～百万级**带 ground truth
> 的试验数据集，喂给**现有** Agent 做规模化评估。
>
> **换数据源不动 Agent**：数据集通过 `SyntheticEvidenceSource` 实现与 `EvidenceStore`
> 同构的四查询协议，`AgentLoop` / `InvestigationTools` 一行不改。

---

## 1. 为什么需要它

原有评估集极小（MuJoCo n=6、合成 n=6），"准确率 1.0" 建立在个位数样本上，
**不具统计意义**，也无法回答**误报率**这种真问题。本数据集用忠实物理仿真把样本量
拉到有统计意义，并**如实暴露**评估器（确定性 provider）的隐藏假设。

**三条口径**（已与需求方确认）：
1. **1 条记录 = 一段试验（trial）**，不是一条遥测点。
2. **用途 = 评估现有 Agent**（不是训练）。
3. **保真度 = 加真实噪声模型**，不做理想化数据。

---

## 2. 架构（四层）

```
conditions.py        试验条件网格 + 分层采样（决定"一条 trial 是什么"、"百万条怎么分布"）
      │
      ▼
gait.py              trot 步态控制器（自由基座真走路 / 吊挂 / 微摆 三档）
      │
      ▼
simulate.py          MuJoCo 跑 Go2 → 关节力矩/电流 + 一阶热模型温度 + 基座位姿
      │
      ▼
noise.py             真值 → 噪声层 → 观测（量化/齿槽/延迟/抖动/电池sag/电流偏置/热噪/丢包）
      │
      ▼
gen_dataset.py       ProcessPool 分片并行 + 断点续跑 → manifest JSONL
      │
      ▼
dataset_eval.py      分层抽样 → 按 config 重放仿真 → 现有 Agent 调查 → accuracy/recall/FP/Wilson CI
```

## 3. 保真度档次（诚实标注，绝不冒充）

| 档 | 含义 | 是否完整运动学 | 说明 |
|---|---|---|---|
| `free`（默认主路径） | 自由基座 trot，狗自己平衡 | ✅ 是 | 最还原；可能翻倒（`fell` 判据事后标注） |
| `suspended` | 基座加竖直弱弹簧支撑，腿仍摆动受力 | ❌ 否 | 排除"摔倒"失败模式，但垂直运动被约束 |
| `micro_swing` | 退回站立微幅摆动（无步态） | ❌ 否 | 最后兜底；负载调制很弱 |

**每档都带保真度标签，`suspended`/`micro_swing` 绝不冒充"真走路"。**
自由基座翻倒的 trial **保留并标 `fell=true`**、从评估池剔除并计数，**不悄悄丢**。

### trot 步态原理

四足对角步态：**对角两条腿同相**（FL+RR 一组，FR+RL 一组），两组相位差 π。
- **支撑相**（s < duty）：腿伸直、**线性后扫** → 足着地推动机身。
- **摆动相**（s ≥ duty）：腿抬起（膝更弯）+ **快速前摆** → 足离地跨过地面。

支撑相后扫大半周期、摆动相快速回位 → 每周期**净前进**。
（对称正弦步态的净位移恒为 0——实测过，故采用**非对称线性扫掠**。）

**这是开环相位驱动**：不做状态估计、不做平衡反馈，**不保证一定不摔**——
稳定性靠 PD 增益与步频/幅度调参，由 `fell` 判据事后标定。这是诚实边界。

## 4. 试验条件与假设值清单

> ⚠️ **以下全部为工程假设值**（先验初值 / 待真机标定），**不是**对某台真机的标定。
> 参数集中在 `conditions._sample_condition` 与 `synth/generator.DEFAULT_PARAMS`，可用真机数据替换。

| 维度 | 取值 | 性质 |
|---|---|---|
| 负载 `payload_kg` | {0, 3, 8, 15} kg | 假设 |
| 坡度 `slope_deg` | {0, ±5, ±10}° | 假设（旋转重力向量实现） |
| 步频 `freq` | {0, 0.5, 1.0, 1.5, 2.0} Hz | 假设 |
| 环温 `t_amb` | {15, 25, 35, 45} °C | 假设（**影响温升判据，见 §6**） |
| 母线电压 `v_bus_oc` | {52, 48, 44, 40} V | 假设 |
| 磨损 `wear_friction/coulomb/rth` | ×{1.0,1.3,1.8} / ×{1.0,1.5,2.0} / ×{1.0,1.2,1.4} | 假设 |
| 故障 | F1桥转/F2热退化/F3丢包/F4电流偏置/F5负载骤增 × severity{0.5,0.8,1.0} | 见 §5 |
| **normal 占比** | **≥ 35%** | **专测误报率** |

**不做全因子**（7 维全因子会爆炸到数亿组合）：改用**分层随机采样**，
关键类别（故障类型、normal 层）**强制**达到目标占比，给定 seed 可复现。

**热模型参数**（一阶）：`kt=0.25 N·m/A, R=0.35Ω, Cth=900 J/K, Rth=0.55 K/W, T_amb=25°C`。
→ 时间常数 `τ = Rth·Cth ≈ 495 s`。**这决定了热故障需要长试验才能测出（见 §6）。**

**噪声层参数**（`noise.NoiseConfig`，全部为假设值）：编码器量化 14 bit、齿槽 0.5 N·m/14 slot、
控制延迟 1 步、采样抖动、电池内阻 0.03Ω（含 0.7·V_oc 截止下界）、电流增益 σ2%/偏置 σ0.1A/
底噪 0.05A、温度观测 σ0.5/过程 σ0.3、丢包率（默认 0，故障时生效）。

## 5. 故障注入

| 故障 | 物理含义 | 注入方式（`to_sample`） |
|---|---|---|
| F1_stall | 卡死/堵转 | 力矩拉到堵转限幅，电流饱和、温度急升 |
| F2_temp_rise | 热退化/散热失效 | 持续大负载 + 产热加大（Rth 恶化） |
| F3_packet_loss | 通信丢包 | 故障窗内随机置 NaN（valid=0） |
| F4_current_bias | 电流传感器零漂 | 故障窗内电流整体 +Δ |
| F5_load_spike | 外部大负载骤增 | 力矩+电流一段突增 |

故障窗 = 试验后段 `[40%, 90%]`（`fault_start_frac` / `fault_end_frac`）。

## 6. 评估结果与**诚实边界**（关键）

### 命令

```bash
PYTHONPATH=src python -m data_dog.synth.dataset_eval --manifest data/mj_60s_100k --n 2000 --seed 7
```

### 当前结果（60s 档，正式集 100,000 条，分层抽 n=2000，确定性 provider）

| 指标 | 值 |
|---|---|
| **总体 accuracy** | **0.844**（Wilson 95%CI 0.827–0.859） |
| F1_stall recall | 1.00（n=261） |
| F2_temp_rise recall | 0.79（n=260） |
| F3_packet_loss recall | 0.75（n=260） |
| F4_current_bias recall | 0.45（n=259） |
| F5_load_spike recall | 0.98（n=259） |
| **normal 误报率 (FP)** | **0.064**（n=701） |

> 5 个独立抽样点（40k/80k/100k 检查点、n=2000、2k 压测集）落在 **83–85%**，收敛。

### 诚实边界（必须一并交代，不得只报分数）

1. **仿真数据 ≠ 真实数据**。真实误报率仍需真机回灌才能定论。
2. **热故障需要长试验**：`τ ≈ 495 s`，2s 档下热故障**物理上测不出**（注入了也来不及升温）。
   故数据集默认时长设为 **60 s**。
3. **电流/温度实测量级**（标称工况，t_amb=25°C，free trot，前左膝）：小跑电流均值
   **~12–13A**，瞬时峰值 **~94A**（**这是 free trot 的普遍特性，正常 trial 峰值同样 ~94A，非故障专属**）；
   60s 档峰值温度仅 **31–36°C**（相对环境抬升 ~7–11°C）。**均够不到检测器 75°C / rise≥25 的热阈值。**
4. **F2 温升召回（0.79）不是靠热阈值**：实测样例峰值 31–36°C，不触发任何热分支；
   命中来自 F2 注入**同时抬高的电流**触发第 5 条电流判据——该电流差实测仅 **~+1.4A**，
   **恰在 1.5A 阈值附近抖动**（3 条样例里中 1 条），故 F2 召回**对工况敏感**。
5. **F4 召回偏低（0.45）的真因＝窗口口径缺陷，不是"信号太弱"**：检测器 F4 判据为
   「全窗电流均值 − 参照均值 > 1.5A」。两处叠加缺陷：(a) **参照窗被污染**——参照取**前半段(0–50%)**，
   而 F4 注入窗是 `[40%, 90%]`，两者**重叠**，+5A 偏置漏进参照被稀释；
   (b) trot 电流**自然前高后低**（全窗均值比前半段低 ~0.4A）。实测 F4 该差仅 **~1.05–1.10A**，
   **恰好卡在 1.5A 阈值之下** → 大量漏判（按此口径实测 0/14 命中）。
   **修法在评估器口径**（对齐参照窗与故障窗、或按标准差归一），**绝不改仿真迁就分数**。
6. **噪声多为假设值**，MuJoCo 不出真实温度（一阶热模型近似）。
7. **吊挂档非完整运动学**，仅兜底（60s 正式集 **100% free_trot**，未用吊挂）。

> **本阶段最大的发现**：忠实数据的价值**不是漂亮的分数**，而是把"评估器判据依赖合成数据隐含假设"
> **逼出来**——已逼出两处：环温硬编码 25°C（曾致 24% 误报，修后 6.5%）、以及上面 F4 的
> **参照窗与故障窗重叠**导致的漏判。需要准确评估时，按**真实量级/口径重新标定**；**绝不**改仿真迁就分数。

## 7. 存储策略

- **manifest 用 JSONL（标量汇总），全时序不物化**：1M 全时序(float64)≈100GB 不可接受；
  标量汇总 ≈300B/条 → 60s 档 10 万条仅数 MB。
- 评估子集**按 (config, seed) 重放仿真**得到，保真且省盘。
- 每 shard 一个 `.jsonl` + `.done/{shard}.ok` 原子标记；`--resume` 跳过已完成分片。
